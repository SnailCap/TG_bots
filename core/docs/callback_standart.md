# Callback Data Standard

## 1. Назначение

Данный документ фиксирует стандарт формирования `callback_data` для всех
Telegram-кнопок во фреймворке interaction-слоя.

Стандарт обязателен для:

-   `UserInputRouter`
-   `Process`
-   `Step`
-   `UI Builder`
-   всех реализаций ботов, использующих фреймворк

Цель стандарта:

-   исключить коллизии строк
-   обеспечить единый механизм маршрутизации
-   чётко разделить инфраструктурные и доменные команды
-   гарантировать расширяемость
-   упростить отладку по логам
-   сохранить чистую архитектуру (separation of concerns)

------------------------------------------------------------------------

## 2. Общий принцип

Инфраструктурные callback-команды обязаны начинаться с префикса:

    svc:

Действия текущего шага используют отдельный короткий префикс:

    st:

Любая `callback_data`, не начинающаяся с `svc:` или `st:`, считается
недопустимой в рамках стандарта.

`svc:` и `st:` являются зарезервированными префиксами
interaction-фреймворка.

------------------------------------------------------------------------

## 3. Пространства имён (Namespaces)

### 3.1 Навигация по страницам

Формат:

    svc:nav:<target>

Примеры:

    svc:nav:previous
    svc:nav:current
    svc:nav:home
    svc:nav:profile

Назначение:

-   переход между страницами
-   управление историей страниц

Обрабатывается: `UserInputRouter`

------------------------------------------------------------------------

### 3.2 Запуск процесса

Формат:

    svc:prc:start:<process_key>

Пример:

    svc:prc:start:buy_subscription

Назначение:

-   запуск зарегистрированного процесса
-   инициализация состояния процесса

Обрабатывается: `UserInputRouter`

------------------------------------------------------------------------

### 3.3 Команды управления процессом

Формат:

    svc:prc:cmd:<command>

Примеры:

    svc:prc:cmd:next
    svc:prc:cmd:prev
    svc:prc:cmd:cancel
    svc:prc:cmd:restart

Назначение:

-   переход между шагами процесса
-   системное управление wizard-flow

Обрабатывается: `Process.handle_input()`

------------------------------------------------------------------------

### 3.4 Действия шага (Step Actions)

Формат:

    st:<action>
    st:<action>:<arg>
    st:<action>:<arg1>:<arg2>

Примеры:

    st:choose_plan
    st:choose_plan:basic
    st:set_language:et
    st:toggle_day:mon

Назначение:

-   доменные действия текущего шага
-   обработка пользовательского выбора
-   изменение временного состояния шага

Обрабатывается: текущим активным `Step`

Router не интерпретирует `st:*`, а передаёт управление активному Step.

------------------------------------------------------------------------

## 4. Формальная структура

Инфраструктурная строка:

    svc:<namespace>:<segment>[:<segment>...]

Шаговая строка:

    st:<segment>[:<segment>...]

Ограничения:

-   используется только ASCII
-   сегменты разделяются `:`
-   допустимые символы: `[a-zA-Z0-9_-]`
-   длина строки не должна превышать 64 байта (ограничение Telegram)

------------------------------------------------------------------------

## 5. Инварианты

1.  Router обрабатывает только `svc:*`.
2.  `svc:nav:*` и `svc:prc:start:*` обрабатываются Router.
3.  `svc:prc:cmd:*` обрабатывается Process.
4.  `st:*` обрабатывается только активным Step.
5.  Нельзя использовать "голые" строки без префикса.
6.  `svc:` и `st:` являются зарезервированными префиксами.
7.  Новые namespace должны быть задокументированы.

------------------------------------------------------------------------

## 6. Разграничение ответственности

  Префикс            Обрабатывает   Назначение
  ------------------ -------------- ------------------------
  `svc:nav:`         Router         Переход по страницам
  `svc:prc:start:`   Router         Запуск процесса
  `svc:prc:cmd:`     Process        Управление шагами
  `st:`              Step           Действия текущего шага

------------------------------------------------------------------------

## 7. Поведение Router

Алгоритм:

1.  Если строка начинается с `svc:` → обработать согласно namespace.
2.  Если строка начинается с `st:` → передать активному Step.
3.  Иначе → логировать как некорректную.

------------------------------------------------------------------------

## 8. Почему нельзя использовать простые строки

Плохая практика:

    back
    continue
    next
    choose_basic

Проблемы:

-   возможные коллизии
-   отсутствие явного уровня ответственности
-   сложность масштабирования
-   невозможность формальной валидации

Правильно:

    svc:nav:previous
    svc:prc:cmd:next
    st:choose_plan:basic

------------------------------------------------------------------------

## 9. Расширение стандарта

Допускается расширение пространства имён:

    svc:dlg:confirm
    svc:notify:ack
    svc:admin:ban

Каждое расширение должно:

-   иметь явного обработчика
-   быть задокументировано
-   соответствовать общей структуре

------------------------------------------------------------------------

## 10. Связь с архитектурой

Стандарт `callback_data` является публичным контрактом
interaction-фреймворка.

Он обеспечивает:

-   предсказуемую маршрутизацию
-   чистое разделение уровней
-   прозрачность логов
-   масштабируемость
-   возможность строгой JSON-валидации

Изменение `svc:` или `st:` является breaking change.

------------------------------------------------------------------------

## 11. Пример полного сценария

    svc:nav:home
    svc:prc:start:buy_subscription
    svc:prc:cmd:next
    st:choose_plan:basic
    svc:prc:cmd:cancel

------------------------------------------------------------------------

## Итог

`svc:` --- инфраструктурный протокол. `st:` --- протокол шаговых
действий.

Такое разделение обеспечивает строгую, но компактную архитектуру
callback-механизма.
