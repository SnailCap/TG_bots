# Callback Data Standard

## 1. Назначение

Данный документ фиксирует стандарт формирования `callback_data` для всех Telegram-кнопок во фреймворке interaction-слоя.

Стандарт обязателен для:

* Router
* Process
* Step
* UI builder
* всех реализаций ботов, использующих фреймворк

Цель стандарта:

* избежать коллизий строк
* обеспечить единый механизм маршрутизации
* разделить инфраструктурные и бизнес-команды
* упростить расширяемость системы

---

## 2. Общий принцип

Все инфраструктурные callback-команды обязаны начинаться с префикса:

```
svc:
```

Любая `callback_data`, не начинающаяся с `svc:`, считается бизнес-логикой страницы или шага.

---

## 3. Пространства имён (Namespaces)

### 3.1 Навигация по страницам

Формат:

```
svc:nav:<target>
```

Примеры:

```
svc:nav:previous
svc:nav:current
svc:nav:home
svc:nav:profile
```

Назначение:

* переход между страницами
* управление историей страниц

Обрабатывается: `UserInputRouter`

---

### 3.2 Запуск процесса

Формат:

```
svc:prc:start:<process_key>
```

Пример:

```
svc:prc:start:buy_subscription
```

Назначение:

* запуск зарегистрированного процесса

Обрабатывается: `UserInputRouter`

---

### 3.3 Команды внутри процесса

Формат:

```
svc:prc:cmd:<command>
```

Примеры:

```
svc:prc:cmd:next
svc:prc:cmd:prev
svc:prc:cmd:cancel
```

Назначение:

* управление шагами процесса
* навигация внутри wizard-flow

Обрабатывается: `Process.handle_input()`

---

## 4. Инварианты

Следующие правила обязательны:

1. Router обрабатывает только callback, начинающиеся с `svc:`.
2. Page и Step не должны обрабатывать `svc:*`.
3. Бизнес callback никогда не должен начинаться с `svc:`.
4. Все новые инфраструктурные команды должны быть добавлены в данный стандарт.
5. Нельзя использовать "голые" строки вроде `back`, `continue`, `next` без namespace.

---

## 5. Разграничение уровней ответственности

| Префикс          | Обрабатывает | Назначение           |
| ---------------- | ------------ | -------------------- |
| `svc:nav:`       | Router       | Переход по страницам |
| `svc:prc:start:` | Router       | Запуск процесса      |
| `svc:prc:cmd:`   | Process      | Управление шагами    |

---

## 6. Почему нельзя использовать простые строки

Пример плохой практики:

```
back
continue
next
```

Проблемы:

* возможные коллизии с бизнес-кнопками
* невозможно понять назначение строки по логам
* сложно масштабировать систему

Правильный вариант:

```
svc:nav:previous
svc:prc:cmd:next
```

По строке сразу видно:

* это системная команда
* кто её должен обработать
* к какому уровню архитектуры она относится

---

## 7. Расширение стандарта

При добавлении новых системных механизмов допускается расширение пространства имён.

Пример:

```
svc:dlg:confirm
svc:notify:ack
svc:admin:ban
```

Любое расширение должно быть отражено в этом документе.

---

## 8. Связь с архитектурой

Стандарт `callback_data` является частью публичного контракта interaction-фреймворка.

Изменение префикса `svc:` является breaking change.

---

## 9. Пример полного сценария

```
svc:nav:home
svc:prc:start:buy_subscription
svc:prc:cmd:next
svc:prc:cmd:cancel
```

Router:

* распознаёт `svc:nav:*`
* распознаёт `svc:prc:start:*`

Process:

* распознаёт `svc:prc:cmd:*`

Все остальные callback передаются текущей странице или шагу.

---

## Итог

`svc:` — единственная точка входа для инфраструктурных callback.

Этот стандарт гарантирует:

* предсказуемый роутинг
* отсутствие конфликтов
* масштабируемость системы
* чистую архитектуру
